# 校园路口信号配时优化智能体 · 使用说明

## 1. 打开项目

双击当前文件夹中的 **start.cmd**。

- 项目看板：[http://127.0.0.1:8765](http://127.0.0.1:8765)
- AGH 工作台：[http://127.0.0.1:4177](http://127.0.0.1:4177)

运行环境与依赖已经安装在本项目的 `.tools` 内，无需全局安装 Python、Node 或 Visual Studio。保持项目文件夹结构完整即可使用。

## 2. 模型账户

本次配置已在 AGH 后台确认。后续更换密钥或模型时，打开 AGH 工作台的“设置 → 模型与账户”，选择 Agnes AI，测试连接、选择默认模型并保存账户。

密钥只在 AGH 本地设置中输入，不填写到源码或看板。`.runtime/agh` 含账户及会话数据，不要上传到公共仓库。

## 3. 执行一次优化

1. 在项目看板选择“课前高峰”等场景。
2. 点击 **在 AGH 运行优化**。
3. 出现工具审批卡片时，检查工具名称及输入，点击 **允许本次调用**。每次批准只对当前调用生效；也可拒绝。
4. AGH 依次读取场景、运行基线、搜索配时、批量仿真候选、校验效果。
5. 等待模型报告和确定性校验结果。候选仿真会执行多个 SUMO 进程，请不要重复启动任务。

AGH 的审批有等待时限，请在卡片出现后及时处理。超时或拒绝会保留相应事件记录；若任务因此没有完成，可重新发起。

## 4. 查看结果

- **四个指标**：车辆平均延误、最大排队、行人平均等待、高峰通过量。
- **仿真回放**：切换固定基线与候选，播放、拖动进度、调整倍速。
- **工具执行记录**：展开查看实际工具输入、返回结果及失败原因。
- **智能体会话与校验过程**：查看真实模型名称、会话编号、工具调用与审批事件；展开模型报告。
- **方案对比**：查看是否满足约束及 5% 延误改善目标。

上方指标显示已有候选或基线。**候选是否采纳，以校验状态为准**；不能仅凭数字变小就认定成功。模型报告是解释，确定性工具的 `comparison.json` 是判断依据。

## 5. 失败与修正

首次校验失败，AGH 将具体失败原因传给搜索工具，最多修正两次。仍不符合目标便保留基线。零流量场景应报告“没有可证明的改善”，不应显示优化成功。

所有交通需求均为合成数据，配时限制是项目假设。本项目只做仿真决策，不连接真实交通信号设备。

## 6. 导出证据

点击 **导出证据包**，保存 ZIP：

- `run/input.json`：场景、约束、随机种子。
- `run/demand.rou.xml`：基线与候选共用的交通需求。
- `run/comparison.json`：指标、约束、失败原因及建议采用的配时。
- `run/` 下的原始 SUMO XML、日志和候选记录。
- `comparison.csv` 与 `report.md`：比较表及简报。
- `tool-receipts.jsonl`：业务工具执行回执。
- `agh-native-session.jsonl`、`agh/`：真实 AGH 会话、事件和逐次审批记录（AGH 任务完成并成功导出时提供）。

页面明确标注本地验算记录与真实 AGH 记录。没有原生会话文件的本地验算不能当作模型执行证明。

## 7. 停止、重启及排错

在项目根目录打开 PowerShell：

```powershell
# 停止本项目两个页面服务
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-services.ps1

# 再次启动
.tools/python/python.exe scripts/start-services.py

# 检查并注册五个 MCP 工具
.tools/python/python.exe scripts/register-mcp.py

# 查看 MCP 状态（应为 ready，5 个工具）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/agh.ps1 mcp status campus-signal
```

请在任务结束后重启服务。出现错误时先查看：

| 问题 | 位置或操作 |
| --- | --- |
| 未配置模型 | AGH 模型账户，检查是否保存默认账户 |
| MCP 不可用 | `scripts/register-mcp.py`；服务 ID 为 `campus-signal` |
| 看板启动失败 | `.runtime/dashboard-stderr.log` |
| AGH 启动失败 | `.runtime/agh-web-stderr.log` |
| 模型任务失败 | `.runtime/jobs/<job_id>/agh-stderr.log` 和 AGH 原生轨迹 |
| 仿真失败 | `.runtime/reports/<run_id>/` 中的 SUMO 日志 |

## 8. 复现本地仿真

```powershell
# 仅运行高峰场景及边界检查
.tools/python/python.exe scripts/verify-project.py --quick

# 全部六个场景及边界检查
.tools/python/python.exe scripts/verify-project.py
```

以上命令由 Python 直接验算，**不经过 AGH 模型**。完整智能体流程请使用看板运行按钮。当前仿真为四个直行车流与独立行人相位，尚未包含转向流和真实观测数据。

若迁移到另一个路径，需重新运行安装脚本更新 Python 路径，并重新注册 MCP。详细环境及指标定义见 [README](README.md)，实际验证结果见 [实施记录](docs/实施记录.md)。
