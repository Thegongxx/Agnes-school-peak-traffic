# 智能体使用与实操手册

## 启动与运行

1. 双击项目根目录 `start.cmd`，打开业务看板与 AGH 工作台。
2. 第一次使用，在 `http://127.0.0.1:4177` 添加 Agnes AI 模型账户：填入密钥、测试连接、选择默认模型、保存账户。密钥保存在本地 AGH 私有目录内。
3. 在 `http://127.0.0.1:8765` 选择场景，点击“在 AGH 运行优化”。
4. AGH 会读取场景，申请调用基线仿真。核对审批卡片中的工具和参数，再点击“允许本次调用”。搜索、候选仿真和校验也按本次调用逐次审批。
5. 观察工具回执与原生会话区。批量仿真期间请等待；模型最终报告不能代替确定性校验结果。
6. 校验通过后查看候选配时；校验未通过时查看具体原因。智能体最多修正两次，仍不满足目标便保留基线。
7. 点击“导出证据包”，保存 ZIP。检查 `run/input.json`、`run/comparison.json`、SUMO 原始 XML 和 `agh-native-session.jsonl`。

## 两个页面分别做什么

| 页面 | 用途 |
| --- | --- |
| 业务看板 8765 | 场景选择、逐次工具审批、轨迹回放、指标比较、原生事件摘要和导出 |
| AGH 工作台 4177 | 模型账户管理、MCP 管理、查看原生对话及轨迹 |

AGH 是任务运行框架；Agnes AI 是推理服务；SUMO 是交通仿真器。前端把三者的结果放在同一实验流程里。

## 正确理解数字

所有需求是合成数据。固定种子生成一份需求 XML，基线与候选重复使用该文件。车辆延误改善不代表排队或通过量一定改善。若选择零流量，系统应报告没有可证明的改善，而不是优化成功。

页面上方四个指标展示当前候选（如果已有）或基线；是否采纳以“校验状态”和 `recommended_plan` 为准。配时约束是项目假设，不是道路交通标准。

## 定位错误

- 任务立即报“未配置模型”：检查账户是否确实保存、默认账户是否启用。
- MCP 不就绪：运行 `scripts/register-mcp.py`，检查 ID 为 `campus-signal` 的本地服务。不要使用过长 ID。
- 仿真超时或参数不合法：查看工具错误和该运行目录内的日志，错误不会被包装为成功。
- 看板显示审批：查看参数后选择本次允许或拒绝，不需要放宽整个会话的权限。
- 服务需要重启：先执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-services.ps1`，再双击 `start.cmd`。停止脚本核对运行时路径和命令，仅停止本项目服务。

## 重建环境

新增依赖和工具都在本项目文件夹内。依次执行安装脚本、Microsoft 编译器提取脚本、AGH 构建脚本与 SDK 构建脚本，按 README 的版本记录操作。复制项目到其他路径后，应重新运行安装脚本更新 Python 的路径配置，并重新注册 MCP。

`.runtime/agh` 可能含模型凭据和会话数据，不应打包发布；导出单个实验的证据包用于展示。
